# 시뮬레이션 관찰 프로토콜

[research-log](research-log.md) 가 "유일하게 하지 않은 검증"으로 남겨둔 항목이다.
400개 조합을 검증하는 동안 한 번도 하지 않은 것 — **실제로 신호를 받아보는 것.**

- 시작일: **2026-08-06**
- 종료 예정: **2027-02-06** (6개월)
- 실주문: **끔** (`ENABLE_LIVE_TRADING=false`)
- 기록 파일: `journal.csv` (매일 09:01 리포트와 함께 자동 기록)

---

## 이것이 검증하는 것과 못 하는 것

**못 한다: 전략이 맞는지.**

거래가 연 6~14회다. 3개월이면 **1~3회**, 6개월이면 **3~7회**. 이 표본으로는
아무것도 판정할 수 없다. 이 저장소의 기록에 그 실수가 이미 두 번 있다 —
거래 1~3회짜리 결과로 전략 순위를 매겼고, 6년으로 늘리자 1등이 꼴찌가 됐다.

6개월 뒤 "잘 나왔으니 맞다" 도, "안 나왔으니 틀렸다" 도 **둘 다 근거가 없다.**

**한다: 내가 규칙을 지킬 수 있는지.**

이건 표본 3회로도 알 수 있다. 한 번이라도 못 지키면 못 지키는 것이다.

| 검증 대상 | 판정 방법 |
|---|---|
| 신호가 실제로 도착하는가 | 매일 09:01 리포트 수신 여부 |
| 계산이 백테스트와 맞는가 | 월 1회 대조 |
| 밴드 규칙을 지킬 수 있는가 | 규칙 위반 0건 |
| 하락장에서 버틸 수 있는가 | −20% 구간에서 임의 매도 0건 |
| 상승장에서 참을 수 있는가 | 비중 축소 신호를 무시 0건 |

**마지막 두 개가 진짜 시험이다.** 나머지는 배관이다.

## 매일 (할 일 없음)

**봇이 09:01 리포트를 보내면서 `journal.csv` 에 자동으로 기록한다.**
손으로 칠 일이 없다 — 매일 명령을 치는 습관은 6개월을 못 간다.

기록되는 것: 날짜 · 종목 · 점수 · 목표비중 · 현재비중 · 격차 · 밴드 판정 ·
(밴드를 벗어났으면) 지시 금액 · 시세.

대부분의 날은 **밴드 안이라 할 일이 없다.** 그 "아무것도 안 함"이 쌓이는
것이 이 관찰의 핵심이다 — 나중에 "그때 왜 안 샀지" 를 복기할 수 있어야 한다.

메모를 남기고 싶은 날만 직접 부른다.

```bash
python3 journal.py --note "..."       # 같은 날 두 번 기록되지는 않는다
python3 journal.py --show             # 최근 기록
python3 journal.py --summary          # 집계
```

## 밴드를 벗어난 날 (실제 판단)

리포트에 `⚠️ 리밸런싱` 이 뜬 날만 해당한다. 6개월에 3~7번 있을 것이다.

```bash
python3 journal.py --act
```

물어보는 대로 답하면 된다. 30초.

```
── 2026-09-14  BTC  목표 0.0% / 현재 55.0%  → 매도 5,500,000 KRW
   1) 집행했다
   2) 집행 안 했다 — 내 판단으로            (규칙 위반으로 기록된다)
   3) 집행 못 했다 — 외부 사유              (위반 아님)
   s) 건너뛰기
   > 2
   왜 안 하셨나요? 솔직할수록 데이터가 됩니다.
   > 며칠 더 오를 것 같아서
```

**집행하기 전에 부른다.** 이게 이 명령의 유일한 규칙이다. 집행한 뒤에 적으면
결과에 맞춰 이유가 바뀐다 — 값이 더 떨어지면 "신호를 믿어서 팔았다" 가 되고
올라가면 "어쩔 수 없이 팔았다" 가 된다. 둘 다 그때 실제로 생각한 것이 아니다.

**2번과 3번을 구분하는 것이 핵심이다.**

- **2번(내 판단)** — 할 수 있었는데 안 했다. 규칙 위반으로 기록된다
- **3번(외부 사유)** — 거래소 점검, 최소 주문금액 미만, 입금 대기. 위반 아님

이 구분을 스스로에게 정직하게 하는 것이 이 관찰의 전부다. 2번을 3번으로
적으면 6개월 뒤 "위반 0건" 이 나오는데, 그건 아무것도 검증하지 않은 것이다.

### 신호 없이 사고팔았다면

밴드와 무관하게 손댄 경우다. 이것도 남긴다.

```bash
python3 journal.py --violation
```

임의 익절 / 임의 진입 / 금액 변경 / 조기 개입 중에서 고르고 이유를 적는다.

## 규칙 위반 (이것만 세면 된다)

수익률보다 이 숫자가 중요하다. **하나라도 나오면 라이브는 아직 이르다.**

| 위반 | 정의 |
|---|---|
| 신호 무시 | 밴드를 벗어났는데 집행하지 않음 (사유 기록 없이) |
| 임의 익절 | 신호가 없는데 팔았다 |
| 임의 진입 | 신호가 없는데 샀다 |
| 금액 변경 | 지시 금액과 다르게 집행했다 |
| 조기 개입 | 09:01 리포트를 기다리지 않고 장중에 판단했다 |
| 파라미터 변경 | 분기 검토 시점이 아닌데 설정을 바꿨다 |

각 위반은 **왜 그랬는지** 를 같이 적는다. 대부분 "무서워서" 나 "확실해 보여서"
일 것이고, 그게 이 관찰에서 얻을 가장 값진 데이터다.

## 월 1회 대조

```bash
python3 backtest.py --portfolio --days 400
```

| 확인 | 허용 오차 |
|---|---|
| 신호 발생 횟수 | 백테스트와 ±1회 |
| 목표 비중 궤적 | 일치해야 함 (불일치 = 버그) |
| 누적 수익 | 슬리피지만큼 백테스트보다 나쁠 것 |

**비중 궤적이 어긋나면 전략 문제가 아니라 코드 문제다.** 그때는 관찰을 멈추고
원인부터 찾는다.

## 분기 1회 — 파라미터 검토

**이때만 설정을 건드린다.** 나머지 기간에는 건드리지 않는다.

검토해도 되는 것:

- 데이터 수집 기간, 리포트 시각 같은 운영 파라미터
- 종목 배분 (근거가 있을 때만)

검토하면 안 되는 것:

- 가중치 0.45 / 0.35 / 0.20
- `SCORE_FLOOR` 0.50
- 슈퍼트렌드 (10, 3.0)
- `REBAL_BAND` 0.10

이유는 [research-log](research-log.md) 에 있다 — 이 값들은 뾰족한 최적점이
아니라 고원이고, 격자 20칸이 모두 개선을 보였다. **최근 6개월 성적을 보고
조정하면 그 6개월에 과적합하는 것이다.**

## 6개월 뒤 판정

### 라이브로 넘어가도 되는 조건

전부 충족해야 한다.

- [ ] 규칙 위반 **0건**
- [ ] 리포트 미수신 3일 이하
- [ ] 월간 대조에서 비중 궤적 불일치 0건
- [ ] 최소 한 번의 −15% 이상 하락 구간을 규칙대로 통과
- [ ] 백테스트 대비 수익 오차가 슬리피지로 설명됨

수익률은 조건에 없다. **6개월 수익은 표본 3~7회짜리 잡음이다.**

### 그만두는 조건

미리 정해둔다. 나중에 정하면 합리화한다.

- 규칙 위반이 3건 이상 → **전략이 아니라 나와 맞지 않는 것이다.** 단순 보유나
  적립식으로 간다
- 비중 궤적 불일치가 반복 → 코드를 못 믿는 상태. 라이브 금지
- 매일 리포트를 보는 것이 스트레스 → 이 방식 자체를 재고한다

### 판정하지 않는 것

- 전략이 단순 보유를 이기는지 — **표본이 없다**
- 파라미터가 최적인지 — **6개월로는 알 수 없다**
