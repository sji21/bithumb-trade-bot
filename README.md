# trade_bot

일봉 3신호로 목표 비중을 계산해 텔레그램으로 알리는 개인용 봇.
신호는 바이낸스(USDT) 캔들로 계산하고, 주문 경로는 빗썸 Open API 2.0(KRW)으로 낸다.

> **현재 알림 전용으로 동작한다.** 비중 조정이 자산당 연 12회 안팎이라 자동매매가 필요하지 않아
> 목표 비중만 전송하고 주문은 수동으로 집행한다.

## 전략 요약

```
점수 = 0.45×(MA20 > MA60) + 0.35×(슈퍼트렌드 10,3) + 0.20×(MA50 > MA200)

점수 < 0.5  →  비중 0%
점수 ≥ 0.5  →  비중 = 점수 (55 ~ 100%)
```

BTC 70% / ETH 30% 배분, SOL 은 차트만 관찰. 리밸런싱 밴드 10%p.

**수익을 늘리는 전략이 아니라 낙폭을 줄이는 전략이다.**
2018-03 ~ 2026-11 기준 최대 낙폭 −77% → −42%. 평균 보유 비중이 44% 라서 생기는 효과다.
단순 보유보다 수익이 높은지는 시작 시점에 달렸다 — 3년 구간 70개 중 절반에서만 앞선다.
같은 비중을 그냥 들고 있는 것보다는 수익이 높았지만(연환산 36% 대 15%), 우연이 아니라고 말할 만큼은 아니다.
재현: `python3 evaluate.py --end 2026-11-19` · 상세는 [재검토 기록](docs/review-2026-11.md)

## 설정

```bash
pip3 install -r requirements.txt
cp .env.example .env   # 값을 채운다
```

실행 모드는 두 플래그로 결정된다.

| `ENABLE_LIVE_TRADING` | `ENABLE_LIVE_SIMULATION` | 동작 |
|---|---|---|
| `false` | — | **현재 설정.** 알림만. 주문을 만들지 않음 |
| `true` | `true` | 라이브 경로를 그대로 밟되 mock 영수증만 기록 |
| `true` | `false` | **실주문** |

## 실행

```bash
python3 bot.py
```

macOS 에서는 launchd 로 상시 실행한다 (`~/Library/LaunchAgents/ai.tradebot.bot.plist`).

```bash
launchctl kickstart -k gui/$(id -u)/ai.tradebot.bot   # 재시작
```

## 관찰 일지

실주문을 켜기 전 6개월간 신호를 받아보며 규칙을 지킬 수 있는지 확인한다.
프로토콜은 [rehearsal.md](docs/rehearsal.md).

```bash
python3 journal.py --act            # 밴드 이탈 건에 답한다 (집행하기 전에)
python3 journal.py --violation      # 신호 없이 사고팔았을 때
python3 journal.py --summary        # 밴드 이탈·집행률·규칙 위반 집계
python3 journal.py --show           # 최근 기록
```

평소에는 아무것도 안 해도 된다. 매일 09:01 리포트가 나가면서 봇이 기록한다.
**`--act` 만 사람이 부른다** — 리포트에 `⚠️ 리밸런싱` 이 뜬 날, 6개월에 3~7번.

`--act` 는 집행 **전에** 부른다. 집행한 뒤에 적으면 결과에 맞춰 이유가 바뀐다.

`journal.csv` 는 실제 보유 비중이 들어가므로 gitignore 되어 있다.

## 테스트

```bash
python3 -m unittest discover -s tests
```

표준 `unittest` 라 추가 의존성이 없고 네트워크도 쓰지 않는다. 42개 전부
실제로 터졌던 문제에서 나왔다 — RSI 가 손실 0 구간에서 `pd.NA` 를 반환해
리포트가 죽은 것, 워밍업 부족이 조용히 신호 꺼짐으로 섞인 것, 리밸런싱
밴드가 구현되지 않았던 것, 백테스트가 평가 구간 안의 데이터만으로 지표를
계산해 문서 숫자와 어긋난 것. 새 버그를 찾는 게 아니라 고친 것이 다시
무너지지 않게 하는 용도다.

## 백테스트

```bash
python3 evaluate.py --end 2026-11-19                                   # 재검토 기록의 숫자 전부
python3 backtest.py --portfolio --start 2020-08-07 --end 2026-08-06    # 채택 전략, 구간 고정
python3 backtest.py --end 2026-11-19                                   # 종목별 (최근 6년)
python3 backtest.py --legacy                                           # 폐기된 4시간봉 EMA 크로스
```

**문서에 싣는 숫자는 `--end` 를 고정한 명령의 출력이어야 한다.** 구간을 고정하지 않으면
실행한 날에 따라 값이 달라진다. 2026-08 에는 재현 명령을 적어 두고도 실행해 대조하지 않아,
문서의 표와 스크립트 출력이 서로 달랐다([경위](docs/review-2026-11.md#재현되지-않은-이유)).

일봉 전략은 평가 구간보다 앞선 데이터로 지표를 채운 뒤 평가한다. 시세는 `data/` 에 캐시한다.

봇이 실제로 쓰는 `strategy` 모듈을 그대로 불러 쓴다. 신호 로직을 따로 구현하면
실매매와 어긋난 결과를 보게 되므로 의도적으로 재사용한다.

체결가를 바이낸스 달러 종가로 가정하고 환율과 빗썸 가격 차이를 무시한다.
신호대로 실제로 사고판 기록은 아직 없으므로, 실제 성적이 백테스트와 얼마나 다른지는 모른다.

## 빗썸 API 2.0 메모

구 1.0(`/public`, `/info`, HMAC-SHA512 + `Api-Sign`)은 종료 예정이라 쓰지 않는다.

- 인증: JWT(HS256). 쿼리가 있으면 `query_hash`(SHA512) 포함
- 마켓 코드: `KRW-BTC` 형식. `BTC-KRW` 는 **존재하지 않는 마켓**이라 400 으로 거부된다
- 시장가 주문 규격이 방향에 따라 다르다
  - 매수 `ord_type='price'` + `price`(총 KRW)
  - 매도 `ord_type='market'` + `volume`(코인 수량)
- **IP 화이트리스트 필수.** 미등록 IP 는 `403 NotAllowIP`. 봇은 이 상태를 감지하면
  현재 공인 IP 를 담아 텔레그램으로 알린다 (조용히 실패해 몇 달간 방치된 적이 있다)
